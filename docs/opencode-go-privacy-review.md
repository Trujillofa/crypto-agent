# OpenCode Go sentiment fallback review

Reviewed 2026-11-03. This is a point-in-time policy assessment, not a continuing guarantee. Recheck provider terms and workspace settings before enabling or deploying this route.

* [Go privacy table and usage terms](https://opencode.ai/v2/docs/console/go): `beam-free` is listed as not used for training, with 30-day retention. `iceman-contributor-free` is used for model improvement and is not ZDR. The Go list is not the same as the [Console free model list](https://opencode.ai/v2/docs/console/models); do not infer Go approval from Console model names.
* The same Go documentation says the service is designed for coding agents and clients should send typical coding agent traffic, identify their own user agent, and send a stable session ID per conversation. Sentiment analysis is not typical coding agent traffic. **Do not enable/deploy this use without resolving provider suitability/permission.** The route probe below does not establish permission for sentiment traffic.
* The Go privacy table lists paid `glm-5.3-flash` as no training, zero days. It lists `deepseek-v4.1-flash` similarly, but explicitly says its ZDR agreement was valid only through 2026-10-31 and is renewed monthly; current protection is unverified. DeepSeek also requires enabling the Global region. Paid Go fallback is intentionally not added: usage may incur charges and current DeepSeek privacy is unverified.
* A synthetic coding-only probe against the configured Go endpoint and existing key on 2026-11-03 advertised all three models. `beam-free` and `glm-5.3-flash` returned HTTP success and nonempty content; `deepseek-v4.1-flash` returned HTTP success but no content with an 80-token limit. No trading data or orders were used. A successful HTTP response does not prove sentiment output validity, future availability, or permission.
* The user accepts 30-day retention **only for crypto sentiment**, conditional on provider permission. This is not permission to send overseer chat, portfolio summaries, open positions, risk information, chat history, or general questions to Go. Provider permission for sentiment remains unestablished. The allowlist is not an authorization.
* This draft disconnects Go from every application client, even if the existing enable flag and key are set; chat also excludes Go unless explicitly labeled sentiment. These changes are not deployed: the currently running version may behave differently. When primary fails, other configured providers may still receive the request under their own settings; this change does not establish permission for those routes. No account settings or live services were changed. Direct construction of XAIClient with a Go key and a sentiment workload is technically possible; application builders do not do so. Re-enablement requires a reviewed code change after provider permission and scope are verified, not merely flipping the old flag.
* The reviewed free selector uses an exact allowlist intersected with the live Go catalog, refreshed daily, and fails closed when empty. `beam-free` retention is **not** zero. Catalog metadata alone does not prove current privacy policy. Review the allowlist when policy, availability, or intended use changes.

## Alternatives investigated (2026-11-03)

* [Groq data controls](https://console.groq.com/docs/your-data) describe opt-in ZDR, with usage metadata retained; without ZDR, troubleshooting/abuse logs may retain inputs and outputs for up to 30 days or longer if legally required. Its [acceptable-use policy](https://console.groq.com/docs/legal/ai-policy) restricts automated decisions with a material detrimental impact on individual rights without human supervision in finance, and requires consequential-use safeguards; the [service agreement](https://console.groq.com/docs/legal/services-agreement) also subjects third-party models to their terms and says the services are not for consumer use. Applicability to this specific automated strategy, account eligibility, model terms, cost, and actual access remain unverified. Not a confirmed permitted route.
* [OpenRouter data collection](https://openrouter.ai/docs/guides/privacy/data-collection) says prompt storage and product-improvement use are opt-in at the router, with metadata retained and anonymous categorization of some prompts. Downstream model/provider terms and retention still apply; endpoint selection, trading permissions, account settings, cost, and performance remain unverified. Not a confirmed permitted route.
* Local inference could avoid external prompt disclosure, but hardware capacity, model licensing, sentiment quality and latency have not been established. No alternative has been proven permitted and viable; none was enabled or tested with trading data. All need separate privacy, suitability, cost, and operational review.
